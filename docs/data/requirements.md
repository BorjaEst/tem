# Data module requirements

This document defines functional and non-functional requirements for the data
generation stack in `torch_tem.data` (Lightning `DataModule` and `TEMDataset`).

The data stack is responsible for generating a **stream of rollout chunks** for
training and evaluation, while supporting deterministic repeatability for
validation/test and providing contracts that downstream diagnostics (trace
collection) and figure generation can rely on.

## Definitions

- **Split**: One of `train`, `validate`, or `test`.
- **Stream**: The sequence of batches produced by iterating a split’s dataset.
- **Chunk**: A fixed-length segment of a longer walk with exactly `n_rollout`

  timesteps.

- **Walk**: A longer sequence of world steps generated by an environment and

  then consumed over multiple chunks.

- **Evaluation stream**: The validation/test stream for a given epoch, which is

  deterministic and repeatable.

- **Stream reset**: Resetting the evaluation stream to its deterministic initial

  state once per validation/test epoch (not between chunks).

- **World swap**: Replacing the `World` instance for an environment slot while

  iterating a finite evaluation stream.

## Requirements (EARS notation)

### Split construction and iteration

- **REQ-001 (Split availability)**: WHEN `DataModule.setup(stage)` is called,

  THE SYSTEM SHALL initialize datasets for enabled splits according to config.

- **REQ-002 (Training stream)**: WHEN iterating the training dataset,

  THE SYSTEM SHALL yield an infinite stream of batches.

- **REQ-003 (Evaluation stream)**: WHEN iterating the validation/test dataset,

  THE SYSTEM SHALL yield a finite stream of exactly `max_batches` batches.

### Batch and tensor contracts

- **REQ-010 (Batch shape contract)**: WHEN a dataset yields a batch,

  THE SYSTEM SHALL return a tuple `(chunk, visited)`.

- **REQ-011 (Chunk length)**: WHEN a dataset yields `chunk`, THE SYSTEM SHALL

  ensure `len(chunk) == n_rollout`.

- **REQ-012 (Batch size)**: WHEN a dataset yields `chunk`, THE SYSTEM SHALL

  ensure each timestep contains `B == batch_size` parallel environments.

- **REQ-013 (Visited mask)**: WHEN a dataset yields `visited`, THE SYSTEM SHALL

  ensure it is indexable as `visited[env_i][loc_id]` and aligned to the batch’s
  environments.

### Determinism and repeatability

- **REQ-020 (Seeded repeatability)**: WHEN a seed is configured for the

  validation/test split, THE SYSTEM SHALL produce identical batches across runs
  given the same code and configuration.

- **REQ-021 (Stream reset API)**: WHEN an evaluation split is reset,

  THE SYSTEM SHALL restore deterministic initial RNG state and recreate the
  initial environments, walks, and visited masks.

- **REQ-022 (No global RNG dependence)**: WHEN generating seeded

  validation/test data, THE SYSTEM SHALL NOT rely on global random state.

### No world swaps during evaluation (robust continuous episodes)

- **REQ-030 (No mid-stream world swaps)**: WHEN iterating a seeded, finite

  validation/test stream, THE SYSTEM SHALL NOT swap `World` instances mid-stream.

- **REQ-031 (Sufficient walk length)**: WHEN building a seeded, finite

  validation/test stream, THE SYSTEM SHALL ensure that each per-environment walk
  is long enough to serve all batches for that stream without depletion.

- **REQ-032 (Fail fast on depletion)**: IF a validation/test stream would

  require generating a new walk or swapping a `World` to satisfy iteration,
  THEN THE SYSTEM SHALL raise a clear configuration error rather than silently
  regenerating.

Rationale:

- Downstream diagnostics/figures may stitch consecutive chunks into a single

  continuous rollout. Silent world swaps introduce hidden episode boundaries and
  invalidate “continuous episode” assumptions.

### Diagnostics/figures compatibility

- **REQ-040 (Chunking is a transport detail)**: WHEN a client requires a

  continuous rollout longer than `n_rollout`, THE SYSTEM SHALL support obtaining
  it by consuming multiple consecutive chunks from the same evaluation stream.

- **REQ-041 (Stable environment alignment)**: WHEN a batch is yielded,

  THE SYSTEM SHALL ensure the environments referenced by the dataset remain
  aligned with that batch for trace building.

## Constraints

- **CON-001 (Stateful dataset)**: The dataset MAY maintain mutable internal

  state (walk buffers, visited masks) as an implementation detail.

- **CON-002 (No multiprocessing workers)**: DataLoader usage SHOULD remain

  compatible with stateful `World` objects (e.g., `num_workers=0`).

## Acceptance criteria

- **AC-001**: Given a seeded validation split, when `reset_split("validate")`

  is called at the start of each validation epoch, then the first validation
  batch is bitwise-identical across epochs (same observations and actions).

- **AC-002**: Given `val_steps = N` and `n_rollout = R`, when iterating the

  validation dataset, then exactly `N` batches are produced and each batch has
  `len(chunk) == R`.

- **AC-003**: Given a seeded validation stream, when iterating all `N` batches,

  then no `World` swap occurs mid-stream.

- **AC-004**: Given a configuration that would deplete a walk during validation,

  when iterating validation, then the system fails with an actionable error
  explaining how to increase walk length or reduce `val_steps`/`n_rollout`.
